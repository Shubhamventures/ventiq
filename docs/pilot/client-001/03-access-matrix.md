# Client 001 Access Matrix

## 1. Principle

Access is granted to named users for the agreed pilot fund only. No user receives access merely because they belong to the same organisation.

Use the current governed VENTIQ access model and maintain maker/checker separation for migration activation.

## 3. Minimum operating responsibilities

### Fund Admin

May perform the administrative tasks explicitly permitted by the current VENTIQ role model. For Client 001, nominate as few Fund Admin users as operationally practical.

### Maker

Responsible for:

- checking source completeness;
- submitting governed migration datasets;
- responding to changes requested;
- documenting source/exceptions;
- resubmitting corrected batches.

The pilot must not rely on Maker self-approval.

### Checker

Responsible for:

- independently reviewing submitted migration data;
- approving or requesting changes;
- ensuring material source conflicts are resolved;
- confirming the batch is suitable for activation.

### Finance

Use only the fund-level financial/capital workflow permissions required by the agreed pilot.

### Compliance

Use only the compliance workflow, evidence and approval permissions required by the agreed pilot.

### Investment / Portfolio

Use only the selected fund's portfolio operating data required for the pilot.

### Investor Relations

Use investor-facing operational/document capabilities required by the pilot, subject to fund/investor isolation.

### Investor / LP

Must be restricted to the approved investor identity and permitted fund data/documents. Cross-investor disclosure is prohibited.

## 4. Access acceptance checks

Before go-live:

- every active pilot user has an identified business owner;
- every user is mapped to the intended organisation and fund;
- Maker and Checker responsibilities are documented;
- Investor users have explicit investor scope;
- stale/test/temporary pilot access is removed or clearly segregated;
- unauthenticated access to private routes remains blocked;
- private-document access remains governed;
- access changes are recorded.

## 5. Access change control

Any addition, removal or role change during the pilot must record:

- requester;
- approver;
- effective date;
- old access;
- new access;
- reason;
- fund scope.

## 6. Pilot least-privilege review

Perform a quick access review:

- at initial go-live;
- after any major role change;
- before widening investor access;
- at pilot close.
